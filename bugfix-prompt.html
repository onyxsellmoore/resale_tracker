ISSUE 6 — Purchase date has no default and no calendar picker
═══════════════════════════════════════════════════════════════════

Update AddItemFormTest:
  a. The purchaseDate input has type="date".
  b. On initial render, the purchaseDate input value equals
     today's date formatted as YYYY-MM-DD.
  c. Submitting the form sends purchaseDate as a valid ISO-8601
     date string (not an empty string).

Fix:
- Set the purchaseDate input to type="date".
  This gives a native calendar picker in all modern browsers.
- Initialise the field value to today:
    new Date().toISOString().split('T')[0]
  Use this as the controlled field's initial state — not just
  a defaultValue — so the value is always included in the
  submit payload even if the user does not interact with it.
- When sending to the API, append T00:00:00Z if the backend
  expects a full ISO-8601 Instant rather than a bare date.
  Check CreateItemRequest.java to confirm the expected format
  and adjust accordingly.

ISSUE 7 — Adding inventory items does not work (CRITICAL)
═══════════════════════════════════════════════════════════════════

This is the most important fix. Trace the full add-item path and

Write or update AddItemFormTest:
  a. Submitting a fully valid form calls POST /api/v1/items.
  b. The request body contains all required fields with the correct

Write or update ItemResourceIT (integration test, backend):
  a. POST /api/v1/items with valid body returns 201 and a document
     with a non-null id.
  b. POST /api/v1/items with a missing name returns 400.
  c. POST /api/v1/items with purchasePrice < 0 returns 400.

Investigate and fix every issue found in the following checklist.
Work through each point; fix whatever is broken:

CHECKLIST — FRONTEND:
[ ] API base URL: confirm VITE_API_URL (or equivalent env var) is
    set to http://localhost:8080 in .env.local or vite.config.ts.
    If it is missing, requests go to the wrong host.
[ ] Request body field names: compare what the form sends against
    what CreateItemRequest.java declares. Names must match exactly
    (case-sensitive). Fix whichever side is wrong.
[ ] purchasePrice type: HTML number inputs return strings. Ensure
    the value is cast to Number() or parseFloat() before sending.
[ ] purchaseDate format: if the backend field is Instant, the
    frontend must send a full ISO-8601 string
    (e.g. "2024-03-16T00:00:00Z"), not just "2024-03-16".
[ ] businessId: confirm businessId is included in the request body.
    If auth is not yet wired, hardcode a placeholder UUID that
    matches what the backend expects, and add a TODO comment.
[ ] Error handling: if the fetch throws (network error, non-2xx
    response), the error must surface visibly — not fail silently.
    Add a try/catch or React Query onError handler that displays
    the error message to the user.
[ ] Cache invalidation: after a successful POST, call
    queryClient.invalidateQueries({ queryKey: ['items'] })
    so the table refreshes automatically.

CHECKLIST — BACKEND:
[ ] CORS: open application.properties and confirm:
      quarkus.http.cors=true
      quarkus.http.cors.origins=http://localhost:5173
    If these lines are missing or the origin is wrong, add them.
[ ] CreateItemRequest fields: confirm every field the frontend
    sends has a matching @JsonProperty or matching camelCase name
    in CreateItemRequest.java. Fix any mismatch.
[ ] purchaseDate deserialization: if the field type is Instant,
    confirm Jackson can deserialize ISO-8601 strings. If not, add
    @JsonDeserialize(using = InstantDeserializer.class) or
    register JavaTimeModule in the ObjectMapper config.
[ ] Validation annotations: confirm @NotBlank on name,
    @NotNull @DecimalMin("0") on purchasePrice,
    @NotNull on purchaseDate. Fix any that are missing.
[ ] businessId handling: confirm the endpoint does not reject
    requests that include businessId in the body.

After working through every checklist item, run the app locally
