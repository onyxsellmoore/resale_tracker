Step 1 — Create the Seed Script

Create scripts/seed-dev-user.sh. This script calls the register API to create a test org and admin user. Because passkeys are device-bound, passkey registration happens in the browser — the script only provisions the user record. 

#!/usr/bin/env bash
# seed-dev-user.sh — creates a dev org + admin user via the register API.
# Run this once after starting the stack. Then go to /setup to register your passkey.
# Usage: ./scripts/seed-dev-user.sh [api_url]
# Default api_url: http://localhost:8080

set -euo pipefail
API="${1:-http://localhost:8080}"

# Verify backend is reachable
if ! curl -sf "$API/q/health" > /dev/null 2>&1; then
  echo "✗  Backend not reachable at $API — is it running?"
  exit 1
fi

echo "→ Creating dev org and admin user…"
RESULT=$(curl -sf -X POST "$API/api/v1/auth/register" \
  -H 'Content-Type: application/json' \
  -d '{
    "orgName":        "Dev Org",
    "orgSlug":        "dev-org",
    "adminEmail":     "dev@example.com",
    "adminDisplayName": "Dev Admin"
  }' || true)

# 201 = created, 409 = already exists (both are fine)
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" -X POST "$API/api/v1/auth/register" \
  -H 'Content-Type: application/json' \
  -d '{"orgName":"Dev Org","orgSlug":"dev-org","adminEmail":"dev@example.com","adminDisplayName":"Dev Admin"}')

if [ "$HTTP_CODE" = "201" ] || [ "$HTTP_CODE" = "409" ]; then
  echo ""
  echo "✓  User ready: dev@example.com"
  echo "✓  Org slug:   dev-org"
  echo ""
  echo "→  Next step: open http://localhost:5173/setup"
  echo "   Enter the same email and org slug shown above."
  echo "   Your browser will prompt you to register a passkey (Touch ID / Face ID / Windows Hello)."
  echo "   Do this once — then you can log in at http://localhost:5173/login"
else
  echo "✗  Unexpected HTTP $HTTP_CODE"
  echo "$RESULT"
  exit 1
fi

Section title and structure

## Set up a test user and try the UI

### Prerequisites
The full stack must be running (see "Run locally" above).

### 1 — Create the dev user

Run the seed script from the project root:

```bash
./scripts/seed-dev-user.sh
```

Expected output:
```
✓  User ready: dev@example.com
✓  Org slug:   dev-org
→  Next step: open http://localhost:5173/setup
```

If you see "409" the user already exists — that's fine, skip to step 2.
If you see "Backend not reachable", start the backend first (see above).

### 2 — Register your passkey

Passkeys are stored on your device, not in the database, so you register once
per device.

1. Open **http://localhost:5173/setup** in your browser.
2. Fill in:
   - **Organisation name**: Dev Org
   - **Organisation slug**: dev-org
   - **Display name**: Dev Admin
   - **Email**: dev@example.com
3. Click **Create Organization**.
4. Your browser will prompt you to create a passkey — confirm with Touch ID,
   Face ID, or Windows Hello. On Linux, you may see a PIN prompt instead.
5. You are automatically signed in and redirected to the Analytics page.

> **Troubleshooting**: if step 3 shows "slug already taken", the org was
> already created by the seed script. Navigate directly to
> **http://localhost:5173/login** and enter `dev@example.com` to log in
> using your existing passkey.

### 3 — Explore the app

Once signed in you can:

| Page | URL | What to try |
|---|---|---|
| Analytics | `/analytics` | Default landing page after login |
| Inventory | `/inventory` | Add a new item with a purchase price |
| Sales | `/sales` | Record a sale against an inventory item |
| Users | `/users` | Invite a team member with a different role |

### 4 — Sign out and sign back in

1. Click **Sign out** in the navigation bar.
2. Open **http://localhost:5173/login**.
3. Enter `dev@example.com` and click **Sign in with passkey**.
4. Confirm with your device authenticator — you are redirected to Analytics.

### 5 — Reset test data (optional)

To start fresh, delete all data from the running MongoDB container:

```bash
docker exec -it booking-mongodb-1 mongosh \
  --eval 'use inventorydb; db.dropDatabase()'
```

Then re-run `./scripts/seed-dev-user.sh` and repeat from step 2.
