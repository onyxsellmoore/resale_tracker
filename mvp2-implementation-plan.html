UX Audit — Navigation Shell & Missing States

TDD Frontend Only No Backend
Copy-paste prompt
You are continuing the inventory and sales ledger project.
All existing tests must remain green throughout this prompt.
No backend changes — frontend only.

TASK: UX audit. Add a persistent navigation shell, loading states,
error states, and empty states to every screen.

─── 1. NAVIGATION SHELL ─────────────────────────────────────────

Create a NavBar component:
  Links: Inventory (/inventory) | Sales (/sales) | Analytics (/analytics)
  - Active link is visually distinct (bold, coloured differently).
  - Render the business name on the left (hardcoded string for now).
  - NavBar appears on every page.

Create an AppLayout component:
  - Renders NavBar at the top.
  - Wraps children in a consistent padded content area.
  - Used as the layout route in react-router so every page
    automatically gets the NavBar.

Update react-router routes:
  / → redirect to /inventory
  All other routes rendered inside AppLayout.

─── 2. LOADING, ERROR, AND EMPTY STATES ─────────────────────────

Every screen that fetches data must handle three states clearly.

LoadingSkeleton component:
  - Renders a set of animated placeholder bars.
  - CSS keyframe animation: "pulse" fades opacity 1 → 0.4 → 1.
  - Use inside InventoryTable, SalesTable, and AnalyticsPage
    while React Query is loading.

ErrorMessage component:
  Props: message (string), onRetry (function)
  - Displays the message inside a clearly styled error card.
  - Shows a "Try again" button that calls onRetry.
  - Use inside all data-fetching components when React Query
    returns an error. Call queryClient.refetchQueries on retry.

EmptyState component:
  Props: title (string), description (string), action? (ReactNode)
  - Renders when the fetched list is empty (not loading, no error).
  Use with these messages:
    InventoryTable empty:
      title: "No items yet"
      description: "Add your first item to start tracking inventory."
      action: <button onClick={openAddForm}>Add Item</button>
    SalesTable empty:
      title: "No sales recorded"
      description: "Once you have items in inventory, book your first sale."
      action: <Link to="/inventory">Go to Inventory</Link>
    Analytics empty (date range has no data):
      title: "No data for this period"
      description: "Try selecting a wider date range."

─── 3. NAVIGATION FIXES ─────────────────────────────────────────

After a sale is booked successfully: navigate to /sales.
  (Previously navigated to /inventory — fix this.)

After an item is added successfully:
  - Stay on /inventory.
  - Show a Toast notification: "Item added to inventory."

Toast component:
  Props: message (string), duration? (number, default 3000ms)
  - Appears in the top-right corner.
  - Auto-dismisses after duration milliseconds.
  - Has an ✕ button to dismiss manually.
  - Only one toast visible at a time.

If /sales/new is loaded with ?itemId=X in the URL, the item
dropdown in BookSaleForm must pre-select that item on mount.
Fix this if it is not currently working.

─── 4. TESTS ────────────────────────────────────────────────────

Write all tests FIRST, then implement.

NavBarTest:
  a. Renders "Inventory", "Sales", and "Analytics" links.
  b. The link matching the current route has an "active" class
     or aria-current="page".

LoadingSkeletonTest:
  a. Component renders without crashing.
  b. The rendered element has a class that maps to the pulse animation.

ErrorMessageTest:
  a. Renders the message prop text.
  b. "Try again" button calls onRetry when clicked.

EmptyStateTest:
  a. Renders the title and description props.
  b. Renders the action element when provided.
  c. Renders without crashing when action is omitted.

ToastTest:
  a. Renders the message text.
  b. Calls onDismiss (or disappears) after the duration
     using fake timers (vi.useFakeTimers).
  c. ✕ button dismisses immediately.

Run npm test -- --run. All green before finishing.

Definition of Done

  • NavBar visible on every page, active link highlighted
  • All data-fetching screens show skeleton while loading
  • All data-fetching screens show retry button on error
  • All screens show a meaningful empty state (not a blank page)
  • After booking a sale, user lands on /sales
  • After adding an item, toast appears and user stays on /inventory
  • ?itemId=X pre-selects the item in BookSaleForm
  • All 11 new component tests pass
  • npm test -- --run exits 0

Responsive Layout & Premium Polish

TDD Animation No Backend
Copy-paste prompt
Continue. All existing tests must remain green.
No backend changes — frontend only.

TASK: Make the application fully responsive and add premium
interactive polish. Tests first on every new behaviour.

─── 1. RESPONSIVE LAYOUT ────────────────────────────────────────

NavBar — mobile behaviour (viewport < 768px):
  - Hide the link labels; show a hamburger icon (☰) button.
  - Clicking the hamburger opens a full-width nav drawer
    that slides down from the top.
  - Clicking any link or clicking outside closes the drawer.
  - Hamburger button has aria-expanded reflecting open/closed state.
  - On desktop (≥ 768px): drawer hidden, normal horizontal nav shown.

Tables — all three tables (Inventory, Sales, Category):
  - Wrap each table in a div with overflow-x: auto and
    -webkit-overflow-scrolling: touch.
  - Tables must not clip or overflow the viewport on mobile.
  - On mobile (< 600px): hide lower-priority columns.
    Inventory: hide "Description" and "Notes" columns.
    Sales: hide "Notes" column.
    Use CSS class "hide-mobile" + media query visibility toggle.

Forms — all forms (AddItemForm, BookSaleForm):
  - Single-column layout on mobile: labels above inputs,
    inputs full-width.
  - Two-column layout on desktop (≥ 768px) where it makes sense
    (e.g., Brand + Category side by side, Price + Date side by side).

Analytics SummaryCards grid:
  - Mobile (< 600px): 2 cards per row.
  - Desktop (≥ 900px): 3 cards per row (or all 6 in two rows of 3).
  - Use CSS Grid with auto-fit and minmax(180px, 1fr).

─── 2. PAGE TRANSITIONS ─────────────────────────────────────────

Add a fade-in animation on every page mount.
In index.css add:

@keyframes pageEnter {
  from { opacity: 0; transform: translateY(6px); }
  to   { opacity: 1; transform: translateY(0); }
}

Apply to each top-level page component's root element:
  animation: pageEnter 0.2s ease-out;

─── 3. ANIMATED NUMBER COUNTER ──────────────────────────────────

Create a useCountUp hook:
  Signature: useCountUp(target: number, duration?: number): number
  - Returns 0 on first render.
  - Counts up from 0 to target over duration ms (default 600).
  - Uses requestAnimationFrame for smooth animation.
  - Returns target immediately if target is 0 or duration is 0.

Apply useCountUp to these values in AnalyticsPage:
  - Items Sold count
  - Total Revenue (pass the numeric value; display as currency)
  - Total Profit (pass the numeric value; display as currency)

─── 4. COLUMN SORTING ON TABLES ─────────────────────────────────

Add sort-by-column to InventoryTable and SalesTable.
  - Clicking a column header toggles sort: asc → desc → none.
  - Sorted column shows a ▲ or ▼ indicator.
  - Sorting is client-side (sort the already-fetched array).
  - Default sort: newest first (createdAt for items, soldAt for sales).
  Sortable columns:
    InventoryTable: Name, Brand, Purchase Price, Date Purchased.
    SalesTable: Platform, Sale Price, Profit, Date Sold.

─── 5. TESTS ────────────────────────────────────────────────────

Write all tests first.

HamburgerMenuTest:
  a. On render, aria-expanded on the button is "false".
  b. Clicking the button sets aria-expanded to "true" and the
     drawer becomes visible.
  c. Clicking the button again sets aria-expanded to "false".

useCountUpTest:
  a. Returns 0 on the first render.
  b. Returns the target value once the duration has elapsed
     (use vi.useFakeTimers and advance timers by duration ms).
  c. Returns 0 immediately when target is 0.

TableSortTest (shared test for both tables):
  a. Clicking a sortable header once sorts rows ascending.
  b. Clicking the same header again sorts rows descending.
  c. A sort indicator (▲ or ▼) is present on the sorted column.

ResponsiveTableTest:
  a. The table's wrapper element has the class or style that
     sets overflow-x to auto.

Run npm test -- --run. All green before finishing.

Definition of Done

  • NavBar collapses to hamburger on mobile; drawer opens/closes correctly
  • All tables horizontally scrollable on small screens
  • Forms single-column on mobile, two-column on desktop
  • Analytics cards grid adapts to 2-column on mobile
  • Every page fades in on mount (pageEnter animation)
  • Items Sold, Revenue, and Profit animate up from 0 on load
  • Both tables sortable by column header click; indicator shown
  • All 8 new tests pass (hamburger ×3, useCountUp ×3, sort ×1, overflow ×1)
  • npm test -- --run exits 0
