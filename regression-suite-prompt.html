Human-Readable Format — JUnit 5 @Nested + @DisplayName

Restructure every test class to use nested groups with display names. This produces readable test trees in Maven output, GitHub Actions, and every IDE without any new dependency. 

@QuarkusTest
@QuarkusTestResource(MongoTestResource.class)
@TestProfile(SecurityEnabledProfile.class)
@DisplayName("Item API")
class ItemResourceTest {

    @Nested @DisplayName("POST /items")
    class Create {
        @Test @DisplayName("valid item → 201 with id")
        void valid() { ... }

        @Test @DisplayName("missing name → 400")
        void missingName() { ... }
    }

    @Nested @DisplayName("role enforcement")
    class Roles {
        @Test @DisplayName("SELLER cannot create item → 403")
        void sellerBlocked() { ... }
    }
}
Every test class in booking-api/src/test must be restructured this way. Method names become the last segment of the display label — keep them descriptive.

Known Problems to Find and Fix

BUGItemResourceTest runs without @TestProfile(SecurityEnabledProfile.class) — all tests pass with no Authorization header, meaning the role checks are never actually exercised. This hides security regressions. Add the profile and fix any tests that break.
GAPNo tests for immutable fields: CONTEXT.md says purchasePrice and purchaseDate cannot change after creation. Write a test that sends a PATCH with these fields and asserts they are silently ignored (value unchanged in response).
GAPNo test for sold-item delete: CONTEXT.md says sold items cannot be soft-deleted. Write a test: create item → record sale → try DELETE → expect 409 (or whichever 4xx the implementation returns — check the source and assert accordingly).
GAPNo test for platformFees > salePrice: SaleResource should reject this as invalid. Write a test. If the validation is missing from the implementation, add it (with failing test first).
GAPNo AnalyticsResource tests: CONTEXT.md shows it exists and is ADMIN+ACCOUNTANT only. Write a full test class covering: valid range returns totals, BUYER/SELLER get 403, unauthenticated gets 401.
CHECKPassword login endpoint: after the passkey migration POST /api/v1/auth/login (password) must no longer exist. Write a test asserting it returns 404 or 405. If the endpoint still exists, remove it.
CHECKNo unauthenticated-request tests: Every protected endpoint should return 401 with no token. Write a parameterized test or a @Nested class covering all protected routes.

Auth Suite

@DisplayName("Auth API")
class AuthResourceTest {

    @Nested @DisplayName("organisation registration")
    class Register {
        @Test @DisplayName("valid request → 201 with orgId + userId + role")
        @Test @DisplayName("duplicate slug → 409")
        @Test @DisplayName("missing field → 400")
        @Test @DisplayName("response contains no password or token")
        // assert response body does NOT contain "password" or "token" keys
    }

    @Nested @DisplayName("passkey registration flow")
    class PasskeyRegistration {
        @Test @DisplayName("begin for existing user → 200 with challenge + rpId")
        @Test @DisplayName("begin for unknown email → 401 (no user enumeration)")
        @Test @DisplayName("complete with valid attestation → 200 accessToken + refreshToken")
        @Test @DisplayName("complete with replayed challenge → 401")
        // call begin once, use challenge in two different complete calls — second must fail
    }

    @Nested @DisplayName("passkey login flow")
    class PasskeyLogin {
        @Test @DisplayName("valid assertion → 200 accessToken + refreshToken")
        @Test @DisplayName("tampered signature → 401")
        @Test @DisplayName("unknown email → 401 identical response")
    }

    @Nested @DisplayName("password login endpoint removed")
    class PasswordLoginGone {
        @Test @DisplayName("POST /api/v1/auth/login → 404 or 405")
        void passwordEndpointDoesNotExist() {
            given().contentType(JSON)
                .body("""{"email":"a@b.com","password":"secret"}""")
                .post("/api/v1/auth/login")
                .then().statusCode(anyOf(is(404), is(405)));
        }
    }

    @Nested @DisplayName("token lifecycle")
    class TokenLifecycle {
        @Test @DisplayName("refresh with valid token → new accessToken")
        @Test @DisplayName("refresh with expired token → 401")
        @Test @DisplayName("logout then refresh → 401")
        @Test @DisplayName("logout with no token → 204 (idempotent)")
    }
}

Execution Order

1
Run baseline: ./mvnw test 2>&1 | tee /tmp/baseline.txt. Record every failure.
2
Restructure first, then extend: Convert each existing test class to @Nested/@DisplayName without changing test logic. Run again — all previous passes must still pass.
3
Add security profile to ItemResourceTest: Add @TestProfile(SecurityEnabledProfile.class). Run. Some tests will now fail (no auth header). That is correct — they were broken before. Fix each by adding a generated JWT per Pattern D in CONTEXT.md.
4
Write gap tests (red): For each row in the coverage matrix and each item in "Known Problems", write a failing test first. One test → one implementation fix → green.
5
Peer review pass: Read every new test as if you're reviewing someone else's PR. Ask: "Can this test ever return a false positive? Is the assertion specific enough? Does it clean up in @BeforeEach?"
6
Final run: ./mvnw test — 0 failures, 0 errors. Do not return until this is the result.

Hard Constraints

MUSTEvery test class uses @BeforeEach deleteAll() on all touched repositories — no state bleeds between tests.
MUSTEvery protected endpoint test uses a JWT generated via authService.generateUserJwt(user) (Pattern D). Never hardcode a token string.
MUSTMoney assertions use exact BigDecimal comparison — equalTo(250.00f) is acceptable for REST-assured, but document why if using float in assertions.
NO NEW DEPSNo Cucumber, no TestNG, no extra libraries. JUnit 5 @Nested/@DisplayName only. The CBOR library is already in pom.xml.
SIMPLICITYIf a gap exposes a missing implementation, fix the implementation with minimal code. No over-engineering.
